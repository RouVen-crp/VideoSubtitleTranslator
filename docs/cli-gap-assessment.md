# zimu CLI 现状与目标差距

评估日期：2026-10-23。依据仓库源码和文档进行静态检查；未进行运行时间基准测试。目标见 [ADR-0001](adr/0001-cli-first-product-direction.md)。

## 已有基础

- `Program.cs` 已有 URL 输入的 CLI 流水线，并支持 `standard`、`meme` 两种模式。
- `PipelineRunner`、`PipelineRegistry` 与配置文件提供可复用的处理步骤。
- Web 工作台已有本地 MP4 输入、任务持久化、顺序队列、阶段检查点、恢复与字幕导出能力，可作为 CLI 工作流的技术基础。
- CLI 翻译阶段已有模块进度和心跳日志；现有产物可使部分步骤跳过重复工作。

## 差距与优先级

| 优先级 | 目标 | 当前情况 |
| --- | --- | --- |
| 1 | `zimu` / `zm` 短命令与无参数引导界面 | 入口仍是 `dotnet run ... <url>` 或 `--web`；尚无安装后的短命令、引导界面和底部按键提示。 |
| 1 | URL 与本地视频共用 CLI 翻译流程 | CLI 只接受 URL；本地 MP4 输入仅在 Web 工作台。 |
| 1 | 正确的 CLI 帮助、错误和脚本契约 | 参数解析较宽松；缺少完整帮助与未知参数校验；缺参和运行异常打印消息后仍可能以成功状态退出。 |
| 1 | 翻译后快速播放带外置字幕的视频 | 尚无 CLI 播放入口、播放器探测及外置 SRT 加载与回退提示。 |
| 1 | SRT 为默认交付，烧录视频可选 | 标准和 meme 配置目前都默认开启视频烧录。 |
| 2 | CLI 任务历史、排队与恢复 | Web 工作台已有持久任务与阶段检查点；CLI 目前主要依靠产物存在时跳过步骤，尚无统一任务列表或显式恢复命令。 |
| 2 | 交互界面逐项加入批量任务 | Web 工作台已有顺序队列；CLI 尚无批量排队入口。 |
| 2 | 统一、可信的终端进度 | 翻译模块有日志，但全流程缺少统一的阶段、条目数、耗时和队列位置视图。 |
| 2 | 减少安装与配置摩擦 | 目前需要 .NET SDK、Python/Whisper、FFmpeg、yt-dlp 和翻译服务配置，且虚拟环境需手动初始化；缺少面向 CLI 的集中依赖检查和简明安装路径。 |
| 2 | 自动校对时避免无意义等待 | 标准模式默认开启校对；当前实现对每对相邻字幕等待约 200 毫秒，即使无需模型请求。 |
| 3 | 产品说明以 CLI 为主 | README 的功能、快速开始和运行方式目前首先介绍 Web 工作台。 |
| 3 | 产品更名 | 面向用户的名称与命令尚未变为 `zimu` / `zm`。内部项目名和 GitHub 仓库名暂未决定同步更改。 |

## 时间代价与评估边界

- **始终转录**：即使视频已有原文字幕，仍需处理完整音频。以 10 分钟视频为例，若实际处理速率分别为实时的 0.5、1、2 倍，转录时间分别约为 20、10、5 分钟。这是换算情景，不是本项目在 macOS 上的实测结果。首次模型下载、模型加载和机器性能会改变实际耗时。[Whisper 官方模型速度比较](https://github.com/openai/whisper#available-models-and-languages)使用 A100，不能作为 Mac 耗时承诺。
- **自动校对**：`ProofreadSubtitleSteps.cs` 只在相邻字幕重复或为空时调用模型，但当前每对相邻字幕都有等待。标准配置的等待间隔为 200 毫秒，因此 100 条字幕约有 20 秒、300 条约有 60 秒的固定等待；触发的模型请求和重试另计。消除无请求时的等待不会改变保留自动校对的产品选择。
- **播放**：只在用户选择播放时探测已安装的兼容播放器；不增加必装播放器。系统默认播放器不一定能自动加载外置 SRT，因此需要清晰的回退提示。

## 范围

当前评估只记录差距和已确认的产品方向，不代表相关功能已实现。现有 Web 工作台保持可用；本阶段不新增 Web 功能，也不开展人工逐句校对、GUI 或 App 开发。
